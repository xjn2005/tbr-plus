# 精简中文 README 设计

## 目标

让中文读者在一分钟内知道 tbr++ 是否适合自己：它是一个本地优先、可留下摘录并重新找到它们的桌面阅读器。

README 不承担产品路线图、完整开发文档或宣传页职责。

## 读者与语气

主要读者是希望使用中文阅读、摘录与本地检索能力的个人读者。语气简洁、具体、克制；不使用夸张承诺或尚未验证的功能描述。

## 首页结构

1. 标题与一句定位：`tbr++`，随后用一句中文说明本地优先阅读、摘录与检索。
2. 三枚徽章：真实 CI 工作流状态、Rust、GPL-2.0-only。徽章仅作状态提示，不使用下载量、星标或不存在的发布版本。
3. `适合你，如果……`：三条短句，说明中文排版、本地批注与跨书检索。
4. `当前支持`：EPUB、TXT、HTML、Haodoo、Markdown；桌面 GUI 与轻量终端阅读器；明确不支持 PDF、云同步和 AI 总结。
5. `快速开始`：Windows 环境下从源码运行的最短命令；不链接不存在的 Release。
6. `怎么使用`：选中—高亮/批注—在批注页回看或导出 Markdown 的三步流程。
7. `本地优先`：数据保存于本机 SQLite，无账号或云同步。
8. `许可证`：GPL-2.0-only 链接。

## 文案与视觉规则

- 正文使用中文标题与短段落；仅保留命令、格式名和许可证名的英文技术词。
- 移除原项目的旧截图：它们与当前 tbr++ 的界面和功能不一致。
- 徽章置于标题下方，最多三枚，使用一致的 flat 风格；CI 徽章链接到本仓库的 `main` 工作流。
- 不添加路线图、贡献指南、完整快捷键表或终端长表格；这些内容应放入后续独立文档。

## 验证

- 检查所有徽章 URL 指向 `xjn2005/tbr-plus` 的 `main` 分支或稳定的公开端点。
- 核对 README 中的功能声明与当前代码、CI 工作流和许可证一致。
- 在 GitHub Markdown 预览中确认首屏不需要滚动即可读完定位、徽章和核心能力。
